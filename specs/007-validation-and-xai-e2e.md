# 007 — Validation and the live xAI completion gate

Status: draft. Depends on [004](004-openai-tts.md), [005](005-xai-tts.md), and [006](006-http-streaming.md), with the smoke runner from [008](008-clone-and-run-smoke-tests.md). **A passing real xAI E2E run is the minimum end goal, not an optional future smoke test.**

## Deliverables

- Standard-library offline tests alongside each implementation, using `unittest.IsolatedAsyncioTestCase` and HTTPX mock/custom transports.
- The clone-and-run `smoke/run.py` suite from 008 exercises the **installed public API** for both providers, not HTTPX or provider internals directly. Its xAI selection is the E2E gate; do not duplicate the same live checks in a separate test harness.
- Explicit runner invocation is live-test opt-in; environment-only credentials and no paid calls in default discovery/CI.
- Buffered and streamed WAV artifacts plus validation evidence after a live run.
- Minimal offline CI, installation/build checks, and runnable README examples once code exists. No PyPI publication in this milestone.

## Runnable commands to deliver

Offline, no keys/network:

```sh
python -m pip install -e .
python -m unittest discover -s tests -p 'test_*.py'
```

Live xAI, intentionally paid (key already set in the shell):

```sh
python smoke/run.py --provider xai
```

Default test discovery never executes smoke calls, even with configured keys. **Explicit xAI selection with missing/blank `XAI_API_KEY` fails configuration, not a skipped/passing test.** Authentication/network/rate failures fail the explicit run. Running `python smoke/run.py` without selection checks whichever keys are configured; unconfigured providers are visibly not run.

## E2E scenario

Use a stable built-in voice and short fixed, nonsensitive text:

- Model: `xai/grok-tts` (also cover bare `xai` in offline resolution tests).
- Voice: `eve`.
- Text: `Hello from the HYBRD Python speech SDK. This is an end-to-end test.`
- Native language: `en`.
- Output: WAV, explicitly 24,000 Hz.
- `max_retries=0`: two happy-path synthesis calls per run, bounded cost; retries are exercised offline.
- Network phase timeout: 60 seconds. Wrap each synthesis/stream consumption in `asyncio.timeout(90)` for an overall test deadline.

Run two paths:

```text
public generate_speech → real xAI POST → result bytes → buffered.wav → WAV validation
public stream_speech   → real xAI POST → iterate/write → streamed.wav → WAV validation
```

Store files under `artifacts/smoke/xai/` (already ignored by Git). Create artifacts only after explicit invocation/precondition checks. Do not log keys or write request/authorization headers. Follow 008's validated-output/partial-file cleanup rules.

## Audio assertions

Use only `io.BytesIO`, `wave`, and `array`/stdlib for checking returned WAVs:

- Nonempty bytes, media type `audio/wav`, provider `xai`, model `grok-tts`.
- Opens as an uncompressed WAV; 24,000 Hz, mono, signed 16-bit PCM (matching the verified provider contract).
- Read PCM frames through EOF; frame data exists, length is a whole number of frames, duration computed from **actual bytes read** is positive and under 60 seconds, and at least one sample is nonzero. Interpret samples as little-endian; byte-swap on big-endian hosts if using `array`.
- Do not trust declared WAV `nframes` alone: streaming WAV headers can use unknown/sentinel lengths. Validate actual payload, and do not require a finalized header frame count that the provider does not promise.
- Buffered metadata has nonnegative full-call latency and expected input character count. Stream metadata has nonnegative setup latency, correct media type, and expected input count.
- Stream yields at least one nonempty chunk and finishes inside the deadline. Do not demand multiple network chunks, compare generated byte equality, or assert identical durations across separate TTS calls.
- Persist both files for listening. A manual listening check confirms intelligible speech and expected words; automated WAV checks establish valid non-silent audio, **not semantic transcription correctness**. STT validation is deferred.

If live xAI returns a different WAV contract, record actual headers/properties, reconcile 005, and fix the implementation/test knowingly; do not weaken validation to "any nonempty response" or secretly add an audio decoder dependency.

## Offline quality gate

Cover 002–006 acceptance cases in the smallest practical tests. Use canned response bytes/JSON; provider tests assert observable requests/results, not private implementation layout. Fixture provenance references the pinned upstream where adapted.

Acceptance evidence must include:

- Tests fail for incorrect xAI/OpenAI request fields, timestamp/SSE bytes masquerading as audio, missing PCM rate, key leakage in error repr, replayed streamed audio, and unclosed responses.
- No actual network calls, secrets, real sleeps, or external codec executables in the offline suite.
- Known intentional differences in `specs/README.md` and provider specs remain visible; do not describe deferred upstream features as covered.

## Installation and CI

- Build sdist/wheel with the conventional backend and a dev-only build frontend (`python -m build`); no custom packaging logic.
- In a clean virtual environment, install the wheel, import public exports, and run at least the offline public API checks against that installed artifact. Do not accidentally import from an editable checkout.
- Verify LICENSE, README attribution/metadata, `py.typed`, and runtime modules are included; no secrets/audio/test artifacts in releases.
- GitHub Actions runs offline tests on Python 3.11 and the newest stable supported Python version selected at implementation time, with read-only permissions and no API secrets. Build/install verification can run on one matrix entry.
- Keep live calls manual/local initially; a public CI workflow is not needed to spend API credits. Never expose credentials to fork PRs.
- README documents actual install/API examples, direct-to-provider key handling, AI-voice disclosure for OpenAI applications, native output formats, streaming lifetime, retry cost risk, and live-test opt-in.

## Done / blocked

Done requires:

1. Offline suite passes for both providers and streaming.
2. Build/clean-install checks and the documented clone-and-run smoke setup pass; both providers' smoke checks exist with offline runner coverage.
3. **Explicit live xAI buffered + streamed WAV E2E passes.**
4. Record date, commit, command, pass/fail, WAV sample properties/duration and artifact paths in a short validation-results section here. No credentials or audio in the commit. Record listening separately as done/not done.

Without keys or provider availability, report blocked/unverified and leave the completion gate open. A skipped test is not a passing E2E. Live OpenAI is optional for this initial gate; explicitly mark its status rather than implying verification.
