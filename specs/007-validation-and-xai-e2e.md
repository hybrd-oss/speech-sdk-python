## Audio assertions

Use only `io.BytesIO`, `wave`, and `array`/stdlib for checking returned WAVs:

- Nonempty bytes, media type `audio/wav`, provider `xai`, model `grok-tts`.
- Opens as an uncompressed WAV; 24,000 Hz, mono, signed 16-bit PCM (matching the verified provider contract).
- Read PCM frames through EOF; frame data exists, length is a whole number of frames, duration computed from **actual bytes read** is positive and under 60 seconds, and at least one sample is nonzero. Interpret samples as little-endian; byte-swap on big-endian hosts if using `array`.
- Do not trust declared WAV `nframes` alone: streaming WAV headers can use unknown/sentinel lengths. Validate actual payload, and do not require a finalized header frame count that the provider does not promise.
- Buffered metadata has nonnegative full-call latency and expected input character count. Stream metadata has nonnegative setup latency, correct media type, and expected input count.
- Stream yields at least one nonempty chunk and finishes inside the deadline. Do not demand multiple network chunks, compare generated byte equality, or assert identical durations across separate TTS calls.
- Persist both files for listening. A manual listening check confirms intelligible speech and expected words; automated WAV checks establish valid non-silent audio, **not semantic transcription correctness**. STT validation is deferred.

If live xAI returns a different WAV contract, record actual headers/properties, reconcile 005, and fix the implementation/test knowingly; do not weaken validation to "any nonempty response" or secretly add an audio decoder dependency.
